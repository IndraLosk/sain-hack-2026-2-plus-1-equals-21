# SAIN Hack 2026 · Кейс 4 «Эксперт как плейлист»

**Команда «2 + 1 = 21» · team02**

---

## О приложении

Приложение — «плейлист экспертов»: пользователь выбирает одного или нескольких экспертов по теме сна и получает по очереди ответы, которые опираются только на базу из **20 научных статей** (CC BY). Эксперты — вымышленные персоны, у каждого своя роль и стиль речи:

- **Сомнолог-клиницист** — говорит механизм → сила доказательств → граница применимости;
- **Биохакер-экспериментатор** — превращает вывод статьи в личную проверку с метрикой и сроком;
- **Нутрициолог здравого смысла** — переводит исследование в одну бытовую замену.

Эксперт никогда не ставит диагнозы, не назначает лечение и не называет дозировки: на небезопасные запросы (атаки) он **мягко отказывает**, предлагает безопасную альтернативу и даёт ссылку на статью и раздел базы.

## Запуск

### Требования (requirements.txt)

Зависимости задокументированы в `requirements.txt` в корне репозитория и ставятся из PyPI при сборке. Специально подобраны так, чтобы **не требовать тяжёлых моделей и GPU** (подробнее — в журнале решений):

| Группа | Пакеты | Зачем |
|---|---|---|
| API / сервер | `fastapi`, `uvicorn[standard]`, `pydantic`, `pydantic-settings`, `python-multipart`, `httpx` | REST + SSE-стрим чата, конфигурация, HTTP-клиент |
| Агент / граф | `langgraph`, `langgraph-checkpoint`, `langgraph-checkpoint-sqlite`, `langchain-core` | LangGraph-агент с чекпойнтами диалогов |
| Документы | `pypdf` | извлечение текста из загружаемых PDF |
| Хранилище | `sqlalchemy[asyncio]`, `aiosqlite`, `asyncpg` | сессии, память, журнал пробелов (SQLite по умолчанию, PostgreSQL опционально) |

> Поиск статей — собственный **BM25-Okapi на чистом Python** (модуль `backend/vectorstore.py`), поэтому в списке нет `chromadb`, `onnxruntime`, `huggingface_hub` и эмбеддинг-моделей.

Установка и запуск одной командой:

```bash
python -m pip install -r requirements.txt
bash start.sh
```

`start.sh` запускает `uvicorn backend.main:app` на `0.0.0.0:${PORT:-8000}` (собранный фронтенд раздаётся тем же приложением). Проверка: открыть `http://localhost:8000`.

### Основные эндпоинты

- `GET /api/v1/catalog` — каталог программ и экспертов;
- `POST /api/v1/chat/stream` — ответ одного эксперта (SSE, с поддержкой остановки);
- `POST /api/v1/chat/stream-multi` — один вопрос всем экспертам (источники общие, стиль разный);
- `GET /api/v1/chat/history` / `DELETE /api/v1/chat/history` — история сессии / «начать заново»;
- `GET, POST, DELETE /api/v1/memory` — память о пользователе (персонализация);
- `GET /api/v1/library` — список статей базы + рекомендованных + реально использованных фрагментов;
- `POST /api/v1/articles/recommend` — добавить статью по ссылке;
- `POST /api/v1/documents/upload` — загрузить `.pdf/.txt/.md` в базу;
- `GET /api/v1/knowledge-gaps` — журнал вопросов, по которым в базе ничего не нашлось;
- `GET /api/v1/health` — состояние LLM, поиска и базы;
- `POST /run` — контракт хакатона: набор запросов кейса 4 → ответы с цитатами и отметками отказа.

## Что именно сделали мы

### Бэкенд (Python, FastAPI + LangGraph)

1. **Ответы «по базе» через BM25, а не по памяти модели.** Вопрос пользователя переводится на английские ключевые слова (статьи в базе англоязычные) и ищется по чанкам 20 статей. Агент обязан отвечать только фактами из найденных фрагментов `[FACTS_ONLY]` и ссылаться на конкретный `article_id` + `section_id` — `backend/agent.py`, `backend/vectorstore.py`.
2. **Медицинский guardrail с двумя уровнями.** Сначала быстрые эвристики по словам‑маркерам (дозировка, схема, диагноз, отмена назначений), затем LLM-проверка сложных формулировок. На атаку агент переводится в «режим безопасности» и даёт мягкий отказ + безопасный шаг вместо запрещённого совета — `backend/llm.py`, `backend/agent.py`.
3. **Три различимых персоны.** У каждого эксперта свой системный промпт и свой «угол подачи»; в режиме «все эксперты» источники ищутся **один раз и общие**, а различается только стиль и структура ответа — это закрывает критерий различимости по тексту, а не по картинкам.
4. **Анти‑галлюцинация.** Если по запросу ничего не нашлось, агент честно говорит, что в базе нет подтверждённых исследований, и даёт один безопасный поведенческий шаг; при сбое LLM выдаёт заранее подготовленный fallback с реальными названиями статей — `backend/agent.py`.
5. **Память и персонализация.** LLM извлекает устойчивые факты о пользователе (режим сна, привычки, ограничения) и подмешивает их в контекст; память хранится в SQLite с дедупликацией — `backend/storage.py`, `backend/agent.py`.
6. **Автоиндексация базы при старте.** Если база пуста, приложение само читает `data/case4-dev.json` (или API хакатона) и индексирует 20 статей за ~2 секунды — `backend/hackapi.py`.
7. **Журнал пробелов знаний.** Вопросы, на которые в базе нет ответа, записываются отдельно, чтобы команда видела, каких тем не хватает — `backend/storage.py`.

### Фронтенд (React + TypeScript + Tailwind)

1. **Экран выбора эксперта.** Три персоны как «треки» — по ним сразу видно разницу ролей; выбор ведёт к разговору.
2. **Разговор с экспертом (SSE).** Поточный вывод ответа, список источников с привязкой к статье и разделу; кнопка «Остановить» прерывает генерацию.
3. **Режим «все эксперты».** Один вопрос — ответы всех трёх экспертов, сгруппированные, чтобы сравнивать подачу (`MultiAnswer`, `stream-multi`).
4. **Вкладки/переключение эксперта** прямо в переписке — можно спросить ещё у другого эксперта, не теряя контекст.
5. **Библиотека статей** (`ArticleLibrary`) — что лежит в базе, что рекомендовали пользователи, и **какие именно фрагменты агент реально использовал** в ответах.
6. **Рекомендация статьи** по ссылке и **загрузка документа** (PDF/TXT/MD) в базу — агент начинает учитывать новую статью после индексации.
7. **Память пользователя** (`MemoryPanel`) — просмотр и очистка фактов о себе.
8. **Переключатель LLM** (`LlmSwitch`) — переключение `gpt-6-luna ↔ deepseek-chat` на лету для разработки.
9. **Тема оформления** (тёмная/светлая) и стриминговый индикатор набора текста.

### Контракт хакатона `POST /run`

На вход принимает набор запросов кейса 4 (одна запись = вопрос + эксперт), на выход отдаёт JSON с ответом по каждому запросу: `text` (в стиле указанного эксперта), `refused` (отказал ли агент) и `citations` (статьи + разделы). Формат совпадает с тем, что принимает `POST /case/4/validate`, ответ возвращается целиком в теле HTTP-ответа — `backend/main.py`.

## Журнал решений

1. **Облачные LLM → прокси‑нейросеть хакатона.** Протестировали несколько OpenAI‑совместимых эндпоинтов: DeepSeek (`deepseek-chat`), Mistral, OpenAI, Google Gemini, Groq и локальный Ollama (`http://127.0.0.1:11434/v1`). Технически контракты и запросы работали, но быстро выяснилось: оплаченных ключей нет (российские карты не проходят, на запросах `403`), а часть провайдеров дополнительно закрыта для России по региональным причинам — OpenAI (403 по IP, карты РФ не принимаются), Google Gemini (эндпоинт из РФ не отвечает, `403`), Mistral (блокировка по IP, с 01.01.2026 — 19‑й пакет санкций ЕС), Groq (`403 Forbidden`), DeepSeek (остаётся платёжный барьер с иностранной картой). Разумнее всего оказалось не бороться с платёжными и региональными барьерами, а использовать уже выданный организаторами прокси нейросети: он единственный разрешённый на стенде (Д5), работает по токену и покрывает все наши задачи.
2. **Локальная Ollama → не разворачивать.** Первым рабочим прототипом стал локальный сервер Ollama — он не зависит ни от региональных блокировок, ни от оплаты. Однако установка была тяжёлой: тянулись крупные библиотеки, развёртывание на новой машине занимало много времени, а это несовместимо со стендом (интернета в runtime нет, лимит репозитория 50 МБ). Отказались в пользу `gpt-6-luna` через прокси — проще, легче и соответствует условиям допуска.
3. **GigaChat API → не использовать.** Пробовали российский сервис GigaChat как доступный без региональных ограничений, но подключать не стали: точную причину уже не восстановить, а продукт и так хорошо закрывается прокси‑нейросетью. Следы этого варианта остались в докстринге `app/vectorstore.py` как описание предыдущего подхода.
4. **Эмбеддинги BAAI/bge-m3 → BM25.** Изначально планировали векторный поиск с эмбеддингами bge-m3 на ONNX (~2.2 ГБ). Отказались после перечитывания инструкции: на стенде нет интернета в runtime, а класть веса моделей в репозиторий (лимит 50 МБ) и ставить их из контейнера запрещено (Д5). Перешли на собственный **BM25‑Okapi на чистом Python** — без моделей, весов и GPU (`backend/vectorstore.py`). Статьи англоязычные, поэтому добавили перевод запроса на английские ключевые слова (LLM с эвристическим fallback).
5. **PostgreSQL → SQLite.** Рассматривали `postgresql+asyncpg` как основное хранилище. Отказались по ограничениям стенда (512 МБ памяти, один контейнер на команду): PostgreSQL для масштаба кейса избыточен. Остановились на SQLite (`aiosqlite`), переход на PostgreSQL оставлен через переменную `DATABASE_URL`.
6. **Docker → нативный запуск через `start.sh`.** Пробовали оформлять серверную часть как Docker‑образ. Отказались: стенд собирает приложение по общему шаблону из `requirements.txt` + `start.sh` и свой `Dockerfile` не использует.
7. **Аватары экспертов → подача текстом.** Планировали проработанные аватары для трёх экспертов как отдельный UI‑блок. Отказались: различия экспертов должны быть **по тексту и стилю**, а не по картинкам (критерий V — различимость по тексту ответа). Экспертов различают «плейлист» и стиль речи.
8. **Интерфейс, перегруженный кнопками → минимализм.** В первой версии главный экран содержал много элементов (источники, память, рекомендация статей в одном ряду). Отказались от перегрузки: вернулись к простой схеме «выбор эксперта → лента сообщений → строка ввода», второстепенные функции убрали в отдельные панели.
9. **Одна модель → резервный провайдер.** Изначально приложение строилось только на `gpt-6-luna`. Добавили переключение на `deepseek-chat` как резерв для разработки и на случай недоступности основной модели; на стенде конфигурация по умолчанию остаётся за `gpt-6-luna`.
